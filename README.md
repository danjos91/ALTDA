Веб-платформа с ИИ-агентом для автоматизированной разработки образовательных программ **ДООП** (дополнительные общеобразовательные программы) и **ДПП ПК** (дополнительные профессиональные программы повышения квалификации), разработанная командой **ALTD** для Академии цифрового развития (АЦР).

Методист описывает запрос в свободной форме, а система пошагово формирует полный учебно-методический комплект: матрицу компетенций (ЗУН), учебный план с точным распределением академических часов, планы лекций, практические задания, тестовые вопросы, календарный учебный график и выгружает готовый документ в формате `.docx`.

---

## Ключевые возможности

- **Пошаговое согласование (Human-in-the-Loop):** генерация полного содержания запускается только после того, как методист выберет и утвердит структуру программы (цель, компетенции, модули и распределение часов).
- **Точный детерминированный расчёт часов:** LLM предлагает структуру и относительные веса тем, а математический распределитель рассчитывает академические часы с точностью до 0,5 часа (лекции, практика, лабораторные, самостоятельная работа и итоговая аттестация). Сумма часов всегда строго сходится с заявленным объёмом (от 16 до 500+ ч).
- **Автоматическая валидация (20+ правил):** встроенный валидатор за миллисекунды проверяет баланс часов, покрытие всех результатов обучения (ЗУН) темами и оценочными средствами, корректность пререквизитов и ключей тестов.
- **Точечная доработка и блокировка узлов:** отредактированные или утверждённые разделы можно заблокировать (`locked`), а перегенерацию запускать точечно — только для выбранных модулей, тем или оценочных материалов.
- **Контроль достоверности источников:** система не выдумывает нормативные акты и профстандарты — неподтверждённые источники явно помечаются в отчёте проверки и итоговом документе.
- **Экспорт в `.docx` и JSON:** готовая программа выгружается в оформленный документ Word или в структурированный `program.json`.
- **Работа с LLM и офлайн-режим (Stub):** поддержка любого OpenAI-совместимого API (GigaChat, Cloud.ru Foundation Models и др.), а также встроенного шаблонного режима для демонстрации и тестирования без ключей API.

## Быстрый старт

Для запуска всей системы требуется только **Docker** и **Docker Compose**.

### 1. Запуск в демонстрационном (Stub) режиме (без API-ключей)

Если переменная `OPENAI_API_KEY` не задана, сервис автоматически запускается в шаблонном режиме:

```bash
cd deploy
docker compose up --build -d
```

### 2. Запуск с подключением LLM (GigaChat / OpenAI-совместимый API)

Укажите параметры подключения к модели через переменные окружения или файл `deploy/.env` (см. пример в [`deploy/.env.example`](deploy/.env.example)):

```bash
cd deploy
OPENAI_API_KEY="ваш_ключ" \
OPENAI_BASE_URL="https://адрес-вашего-шлюза/v1" \
OPENAI_MODEL="GigaChat/GigaChat-3-Pro" \
docker compose up --build -d
```

После сборки контейнеров веб-интерфейс будет доступен по адресу:
👉 **<http://localhost:8000/>**

Остановка сервисов:

```bash
cd deploy
docker compose down
```

## Как пользоваться

Веб-интерфейс разделён на **5 последовательных вкладок**, отражающих рабочий процесс методиста:

1. **Заявка:**
   - Нажмите **«+ Новая заявка»** и введите описание курса в свободной форме (например: *«ДПП ПК Анализ данных на Python, 72 часа, очно-заочная форма, практика не менее 60%»*).
   - Система проанализирует текст, выделит известные параметры и при необходимости предложит ответить на уточняющие вопросы (целевая аудитория, уровень подготовки, область ИТ).
2. **Каркас:**
   - Агент предложит до **3 вариантов структуры** курса с уже рассчитанной сеткой часов по модулям и темам.
   - Выберите подходящий вариант. При необходимости отправьте комментарий для перегенерации структуры или утвердите каркас для перехода к генерации контента.
3. **Содержание:**
   - Просмотрите сгенерированные материалы по каждому модулю и теме: виды учебной работы, подробные планы лекций, практические/семинарские задания с критериями оценивания и банк тестовых вопросов.
   - Вы можете заблокировать удачные узлы от изменений и точечно перегенерировать отдельные темы с комментарием.
4. **Проверка и отчёт:**
   - Ознакомьтесь с отчётом автоматической валидации (ошибки и предупреждения по часам, покрытию компетенций и источникам), а также со статистикой генерации.
5. **Выгрузка:**
   - Скачайте готовый учебно-методический комплект в формате **`.docx`** или исходный документ в формате **`.json`**.

## Для разработчиков

### Архитектура системы

Проект построен из двух микросервисов, общающихся по синхронному HTTP-контракту с единой JSON-схемой программы ([`schema/program.schema.json`](schema/program.schema.json)):

1. **`java-service` (Порт `8000`) — Оркестратор, UI и генерация документов:**
   - Управляет жизненным циклом и состояниями программы (`intake` → `clarifying` → `skeleton_draft` → `skeleton_approved` → `content_draft` → `validated` → `exported`).
   - Отдаёт веб-интерфейс (Single Page Application на чистом JS), обеспечивает версионирование (`If-Match`), историю операций и блокировку узлов.
   - Формирует итоговый `.docx` документ с помощью **Apache POI**.
2. **`go-service` (Порт `8081`) — Вычислительное ядро и работа с LLM:**
   - Единственный сервис, взаимодействующий с LLM (включает процессный семафор конкурентности, таймауты, ретраи с экспоненциальным backoff при `429`/`5xx` и валидацию JSON-ответов).
   - Содержит детерминированный распределитель часов (`allocator`), использующий метод наибольшего остатка (Largest Remainder Method) в полуакадемических часах (шаг `0.5` ч).
   - Выполняет быструю детерминированную проверку программы по 20+ правилам (`validate`).

### Основные HTTP-маршруты

#### Внешнее API (`java-service` на `:8000`)
- `GET /health` — проверка состояния сервиса.
- `POST /programs` — создание новой заявки (асинхронный интерактивный пайплайн).
- `GET /programs/{id}` — получение текущего состояния программы.
- `POST /api/generate` — синхронный сквозной прогон полного цикла до статуса `validated` (для автоматического тестирования).
- `GET /programs/{id}/export.docx` — выгрузка сформированной программы в `.docx`.

#### Внутреннее API движка (`go-service` на `:8081`)
Полное описание форматов запросов и кодов ошибок (`bad_request`, `node_locked`, `schema_invalid`, `llm_error`, `llm_timeout`) приведено в [`docs/API.md`](docs/API.md):

| Маршрут | Назначение |
| --- | --- |
| `GET /v1/health` | Проверка работоспособности Go-сервиса |
| `POST /v1/parse` | Извлечение параметров из текста заявки, формирование уточняющих вопросов и `gapsReport` |
| `POST /v1/skeleton/generate` | Генерация до 3 вариантов каркаса с автоматическим расчётом часов |
| `POST /v1/skeleton/regenerate` | Перегенерация вариантов каркаса или отдельных модулей (с учётом `_meta.locked`) |
| `POST /v1/content` | Генерация полного содержания (или точечная пересборка узлов, переданных в `nodeIds`) |
| `POST /v1/validate` | Проверка программы по всем правилам баланса часов, покрытия ЗУН и целостности ссылок |
| `POST /v1/allocate` | Пересчёт распределения часов после ручных правок с сохранением заблокированных узлов |

### Переменные окружения

Настройки задаются через окружение или файл `deploy/.env` (см. [`deploy/.env.example`](deploy/.env.example) и [`go-service/.env.example`](go-service/.env.example)):

| Переменная | По умолчанию | Описание |
| --- | --- | --- |
| `OPENAI_API_KEY` | *(пусто)* | Ключ API для LLM. Если пуст — включается шаблонный режим (`stub`) |
| `OPENAI_BASE_URL` | `https://api.openai.com/v1` | Базовый URL OpenAI-совместимого шлюза |
| `OPENAI_MODEL` | `GigaChat/GigaChat-3-Pro` | Имя используемой модели |
| `ALTDA_STUB` | `false` | Принудительное включение stub-режима (`true`/`1`) даже при наличии ключа |
| `ALTDA_GO_CLIENT` | `http` | Режим клиента в Java: `http` (реальный Go-сервис) или `mock` (встроенная заглушка) |
| `ALTDA_LLM_CONCURRENCY` | `2` | Максимальное число одновременных запросов к LLM |
| `ALTDA_CONTENT_CONCURRENCY` | `2` | Число параллельно генерируемых тем в `/v1/content` |
| `ALTDA_LLM_MAX_TOKENS` | `4096` | Лимит `max_tokens` на один ответ модели |

### Локальный запуск без Docker и тестирование

**Запуск и тесты Go-сервиса (`:8081`):**
```bash
cd go-service
make run                # Запуск на :8081 (подхватывает .env)
make test               # Запуск модульных и property-based тестов
go test -race ./...     # Проверка с детектором гонок
```

**Запуск и тесты Java-сервиса (`:8000`):**
```bash
cd java-service
ALTDA_GO_CLIENT=http ./run.sh   # Запуск с подключением к локальному Go-сервису
./run.sh                        # Запуск со встроенным mock-клиентом (без Go)
./mvnw test                     # Запуск тестов Java-сервиса
```

**Сквозной интеграционный тест (Smoke Test):**
```bash
curl -s http://localhost:8000/health
curl -s http://localhost:8081/v1/health
./scripts/smoke_test.sh http://localhost:8000
```

Дополнительные инструкции по каждому компоненту доступны в [`java-service/README.md`](java-service/README.md), [`go-service/README.md`](go-service/README.md) и [`deploy/README.md`](deploy/README.md).
